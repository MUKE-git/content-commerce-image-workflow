# 图像去重处理器｜前端规则评审稿

> 状态：使用页已有可运行初版，待视觉审核及部署验证；首页尚未开发。本文记录已讨论确定的前端行为与文案；后端现有能力及完整产品边界见 [PRD](PRD.md)。

## 1. 页面与开发顺序

前端最终使用 Streamlit。顶栏有三个入口：**首页**、**开始使用**、**开发者介绍**。前两项是站内页面；“开发者介绍”在新标签打开个人介绍网站，不开发站内开发者页。链接由项目方后续提供；收到链接前只保留该入口的规划，不放虚构网址。

开发顺序固定为：**先开发使用页，再开发首页，最后接入开发者外部链接**。使用页初版已开始实现，后续继续按此顺序推进。

## 2. 使用页主流程

```text
选择图片 → 核对缩略图、可逐张移除 → 点击“开始处理”
→ 动画等待 → 成功 / 部分失败 / 全部失败 → 下载或处理新图片
```

### 2.1 选择图片

- 灰底上传区有白色加号。电脑用户可拖入图片，或点击后通过系统文件选择窗口浏览不同目录并选择一张或多张图片；手机和平板用户通过系统提供的照片或文件选择界面选图。不支持整文件夹上传。
- 支持 JPG、PNG、WebP。单批至少 1 张、最多 20 张。选择后按原选择顺序显示缩略图，每张可单独移除。删到零张时“开始处理”不可点击。
- **大小限制只看本次所选图片的总文件大小**：选了 N 张，总大小不超过 `N × 10 MB`。例如 1 张不超过 10 MB，10 张合计不超过 100 MB，20 张合计不超过 200 MB。不另外设置逐张 10 MB 限制。实际字节换算与上传组件配置在实现时统一。
- 超过 20 张时提示“最多上传 20 张图像”；总大小超限时提示“图片太大了”。两种情况都让**本次选择整体无效**，清空本次选择并请用户重新选择；不自动截取前 20 张，也不显示超限文件名。
- 格式筛选不能替代服务端校验。实际文件损坏或无法解码时，按处理失败状态反馈。

### 2.2 开始与等待

- 选图只进入核对状态；用户点击“开始处理”才调用后端。没有处理参数或逐阶段控制。
- 处理开始后，上传区、已选缩略图和开始按钮切换为动画等待画面；处理中锁定上传和重复提交。
- 等待画面显示欢快的动效与简短提示，不显示已处理张数、批次总张数、百分比、进度条或逐张状态。动效参考 Streamlit 网页唤醒动画。
- 用户可以最小化电脑浏览器，或短时间切换到手机其他应用，再回到仍打开的原网页标签。首版不做账号、数据库、历史任务或断线找回；若浏览器会话丢失，需重新上传。上线前用部署环境验证常见切换场景，不承诺关闭、刷新页面后仍能取回结果。

### 2.3 完成与下载

- 处理完成后显示欢快的小图和完成提示，不用结果缩略图区分成功与失败。
- 仅一张成功图片时，直接提供该 PNG 的下载按钮，不另提供 ZIP。
- 多张成功图片时，上方提供“下载全部 ZIP”，下方按原上传顺序列出成功文件名和逐张 PNG 下载入口。ZIP 只包含成功结果。手机用户可逐张下载，避免必须解压；保存到系统相册或文件位置由设备与浏览器决定。
- 点击“处理新图片”清空当前页面上一批的上传和结果，回到初始选图状态。首版不保留历史记录。

### 2.4 异常状态

| 情况 | 用户可见反馈 | 后续操作 |
| --- | --- | --- |
| 超过 20 张 | 最多上传 20 张图像 | 本次选择无效，重新选择 |
| 总大小超过 `N × 10 MB` | 图片太大了 | 本次选择无效，重新选择 |
| 部分处理失败 | 部分图片未能处理，其他结果可下载。 | 下载成功结果 ZIP 或逐张 PNG，也可处理新图片 |
| 全部处理失败 | 本次图片未能处理，请重新上传。 | 重新选择图片 |

部分失败时必须如实提示，但不列出失败文件名、逐张失败原因或失败缩略图。后端仍保留逐图结果与错误记录，便于排查；界面只展示上表的简短提示。

“最多上传 20 张图像”与支持格式放在同一行，不再在页面标题下重复张数限制。大小规则单列一行，避免误写为“每张不超过 10 MB”。隐私小字不写具体保存或删除时限；实现与部署后需核对其余数据说明是否准确。

## 4. 首页与开发者入口

- 首页介绍项目用途和实际效果，页面底部用“开始使用”按钮进入使用页。
- 首页默认展开七阶段处理说明：每阶段做什么、采用的技术，以及有依据的技术和素材来源。使用页不显示七阶段或贴纸来源说明。对外表述只说明实际图片变化和已验证结果，不承诺平台查重、审核或推荐效果。
- 效果示例使用可左右拖动分割线的原图与处理后图片对比。选定样本和固定样本测评报告在开发首页时提供和接入；图片与报告须标明对应版本。
- 首页视觉方向尚未确定，预期比使用页更具艺术感和几何元素。使用页视觉方向已选为“明快工作台”：白底、橙色主调、活泼而克制。处理中与完成时使用轻巧愉快的动效，不使用蛋糕或甜品主题。
- 开发者入口仅外链，新标签打开；链接待提供。

## 5. 使用页与后端的对接约定

使用页不是演示流程；点击“开始处理”后必须调用现有 `image_workflow.process_batch`，下载内容必须来自本次调用的真实结果。对接关系如下：

| 使用页行为 | 现有后端接口与处理方式 |
| --- | --- |
| 提交已确认的图片 | 按缩略图当前顺序构造 `ImageInput(name, data)` 列表；移除的图片不提交。调用前在服务端再次检查 1～20 张、格式和 `N × 10 MB` 总量规则。 |
| 开始处理 | 仅在“开始处理”点击后调用一次 `process_batch(items)`；处理中不因 Streamlit 重新运行而重复调用同一批。 |
| 判定结果状态 | 从 `BatchResult.images`、`successful`、`failed` 判断全部成功、部分失败或全部失败；错误详情仅供内部排查，页面按第 2.4 节给出简短提示。 |
| 单张 PNG 下载 | 使用成功项的 `ImageResult.data` 和 `output_name`，不重新生成示意图片。 |
| 多张 PNG 与 ZIP 下载 | 成功项维持后端返回的原输入顺序；批次 ZIP 使用 `BatchResult.to_zip()`，其中不含失败项。 |
| 处理新图片 | 清除当前 Streamlit 会话内的上传确认状态和本次 `BatchResult`；不建立跨批次结果库。 |

现有后端还会拒绝空文件、不支持的实际图像格式和超过 3000 万像素的单图，并以逐图失败结果返回；前端文件扩展名筛选不能代替后端解码检查。Streamlit 页面实现时必须核对处理中画面先于耗时调用呈现，以及完成后结果在原标签页保留至用户下载或点击“处理新图片”。

## 6. 实现前后需核对的事项

- Streamlit 上传组件与自定义上传区域在电脑拖入、系统文件选择和手机选图时的实际行为。
- 超量或超大小时整次选择无效的复位行为，以及移除缩略图后重新添加的状态一致性。
- 部署环境对接近 20 张、总大小接近 200 MB 的批次的内存、处理时间与 ZIP 下载承载能力。这里是验证项目，不代表目前已触碰资源上限。
- 电脑最小化浏览器、手机短时间切到其他应用再返回后的处理与下载行为。
- 上传图片的实际传输、暂存和清理方式；不得根据“处理新图片”清空界面推断服务器端文件已被删除。
