# 电商图片批量处理工具 PRD

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V0.8，评审草案 |
| 产品定位 | 面向内容电商运营的图片批量处理工具 |
| 产品载体 | Streamlit 网页 |
| 文档范围 | 前端网页、后端工作流、内部测评系统 |
| 资料依据 | Coze 导出源码、完善计划、扰动测试表 |

## 1. 背景与问题

内容运营需要重复处理已有商品图片。旧版项目用 Agent 串行调用七个图像工具，工具间反复上传下载图片，且本次导出的源码没有独立批处理入口。用户无法通过一个简洁的网页完成批量上传和结果下载，项目也缺少统一口径的展示用效果报告。

本次产品保留七阶段处理逻辑，将它做成低操作成本的网页工具，并用独立的内部测评系统产出一份固定测试集报告。网页对外只有两个页面；测评系统不面向普通用户。

## 2. 目标、非目标与衡量方式

### 2.1 目标

1. 用户只需上传图片，等待处理，下载结果。
2. 单图和多图都能完成完整的七阶段处理，且各图片结果互不混淆。
3. 产品展示页清楚说明功能、展示效果、提供使用指南和固定测评报告。
4. 用可复核的测试样本与方法说明新版效果和处理效率。

### 2.2 非目标

首版不提供用户可调参数、个人测评报告、账号体系、历史图库、自动发布内容平台或平台查重通过率承诺。它也不要求普通用户理解或操作七个内部阶段。

### 2.3 衡量方式

内部测试记录任务完成率、单图及整批耗时、失败类型、结果可用率和人工复核结论。若在简历或展示页使用“效率提升”数字，必须标明对照方式、样本量及实测结果。具体目标值在基线测试后确定。

## 3. 用户与使用场景

目标用户是需要批量处理已有商品图片的内容运营人员。典型任务是一次上传多张图片，等待系统完成，取得与输入文件一一对应的处理图片。用户不需要选择处理强度、翻转方式、贴纸来源或测评指标。

## 4. 产品结构与主流程

产品展示页呈现功能、示例、固定测评报告和使用指南，引导进入用户使用页。用户使用页执行“上传图片 → 自动处理 → 下载图片或 ZIP”。后端七阶段工作流承担图片处理。独立的内部测评系统使用固定样本运行测试、生成静态报告，再将报告放到产品展示页。

前端网页、后端工作流、测评系统是三个产品组成部分；对外网页仍只有“产品展示”和“用户使用”两个页面。

## 5. 需求清单

### 5.1 前端网页

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FE-01 | P0 | 产品展示页包含功能简介、七阶段概览、原图与结果示例、固定测评报告、使用指南和进入使用页的入口。 | 信息完整，示例与报告使用已记录的测试版本；手机和电脑均可阅读。 |
| FE-02 | P0 | 使用页单批最多上传 20 张常见格式图片。上传后自动开始处理。 | JPG、PNG、WebP 图片可进入处理；第 21 张被明确拒绝；不要求另选参数或逐步确认。 |
| FE-03 | P0 | 页面被动展示处理进度和结果状态。 | 用户能知道正在处理、已完成或失败；失败时能定位到文件。 |
| FE-04 | P0 | 单图提供图片下载，多图提供包含成功结果的 ZIP 下载。 | 下载文件可打开，文件名能对应原输入；部分失败不妨碍成功结果下载。 |
| FE-05 | P0 | 页面展示简短的图案来源说明。 | 说明装饰图案由程序生成；不增加用户处理操作。 |

使用页不展示逐图相似度、处理参数表或下载测评报告，也不设置“处理强度”“翻转”等操作控件。

### 5.2 后端工作流

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| WF-01 | P0 | 每张图片连续执行七个阶段：几何处理、颜色处理、文字图层、贴纸图层、涂鸦图层、合成、导出。首版沿用旧版 1280×1706 像素输出作为比较基线。 | 阶段顺序固定，最终输出可打开且像素尺寸正确；单张失败不会错配其他图片。 |
| WF-02 | P0 | 几何处理前自动检测原图文字，再决定是否水平翻转。 | 检测到文字时不翻转；判断不确定或识别服务失败时保留原方向。用人工标注的有字、无字和难例样本验证规则。 |
| WF-03 | P0 | 批量图片相互隔离。 | 同批多张图的底图、装饰图层和最终图一一对应，不发生覆盖或串图。 |
| WF-04 | P0 | 贴纸使用四种本地图案：叶片、花朵、圆点和线条。 | 无网络时也能生成并叠加图案；生成失败时使用简化图案并记录原因。 |
| WF-05 | P0 | 每张图片独立记录成功或失败。 | 单张失败不终止整批；结果清单与下载包一致。 |
| WF-06 | P1 | 避免七阶段间重复远程上传下载，尽量在一次任务内复用已取得的素材。 | 与旧版相比记录远程请求次数和处理耗时，具体改善以实测为准。 |

贴纸方案选择理由：图片素材网站在当前网络环境无法稳定访问，本地图案不需要申请密钥、下载图片或发起远程请求，能缩短等待时间并避免在线接口成为处理任务的故障点。四种图案在同一批任务内复用，每张图片通过素材组合和摆放位置产生差异。

### 5.3 内部测评系统

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| EV-01 | P0 | 使用固定测试集，包含有字/无字、不同尺寸比例及不同商品画面。 | 样本清单和测试版本可追溯。 |
| EV-02 | P0 | 对固定样本运行旧版或基线方案与新版，保留原图和输出图。 | 报告中的图像与数字能对应到具体样本和版本。 |
| EV-03 | P0 | 生成一次性展示报告，包含样本范围、处理结果、可量化指标、耗时、失败样本和结论。 | 可导出静态报告并放到产品展示页；普通用户上传不触发测评。 |
| EV-04 | P0 | 指标含义和比较方法在报告中说明。 | 不使用来源不明的旧版“总分”，不把离线指标写作平台算法结果。 |

具体指标、图片比较前的对齐方法和报告版式留待后续讨论。本阶段不引入“不同处理强度”这一产品概念；旧资料里的梯度测试只作为历史试验资料。

## 6. 异常与边界

- 图片格式不支持、文件损坏或处理失败时，页面给出可识别的文件名和简短原因。
- 本地图案生成失败时，不应中断整批任务；自动改用简化图案，并在内部记录。
- 多图任务中，成功结果可下载，失败结果不混入下载包。
- 公开展示页只使用选定的固定测试图片与报告，不展示普通用户上传的图片。

## 7. 上线验收

1. 网站只有两个对外页面，展示页和使用页内容符合 FE-01 至 FE-05。
2. 使用页完成“上传 → 自动处理 → 下载”主流程，单图与多图均通过测试。
3. 七阶段运行和文字检测翻转规则符合 WF-01 至 WF-06。
4. 内部测评系统产出的静态报告能在展示页查看，图像、数字、测试版本一致。
5. 记录一次固定测试集的处理耗时、完成率与人工画质复核结果，作为简历描述依据。

## 8. 开工依据与开发验证

后端工作流可以按以下已确定规则开工。这里的验证项由开发和测试得出结果，不是开工前需要产品再次拍板的事项。

| 类型 | 事项 | 处理方式 |
| --- | --- | --- |
| 已确定 | 输出尺寸与批量上限 | 首版沿用旧版 1280×1706 像素；单批最多 20 张。 |
| 已确定 | 文字与翻转 | 自动检测文字；检测到文字或结果不确定时不翻转。 |
| 已确定 | 贴纸来源 | 使用本地生成图案；不依赖在线素材接口。 |
| 开发验证 | 文件体积上限 | 根据 20 张图片的内存与耗时测试设定。 |
| 开发验证 | 文字检测阈值 | 用人工标注样本验证，优先避免有字图片被翻转。 |
| 开发验证 | 本地图案效果 | 用固定样本检查图案叠加后的画面可用性与处理耗时。 |

内部测评系统的指标、比较口径和报告版式按用户要求在后续讨论。
